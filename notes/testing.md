# 测试

<h2 class="sec-02">测试文档的撰写</h2>

测试文档的界限，职责要划清，明确哪个信息只属于哪个文档，生命周期如何，文档的变更频率怎么样，文档之间做指向引用，而非重复复制。

一般包含 3 类文档：

| 文档 | 管什么 | 变更方式 |
| --- | --- | --- |
| `TEST_PLAN.md` | 测试总计划 | 长期稳定，不轻易修改 |
| `TESTING_GUIDE.md` | 测试实施规范 | 长期稳定，不轻易修改 |
| `TEST_STATUS.md` | 测试进度与结果 | 每次验收**覆盖更新**，而非追加 |

以Aurora为例：

### `TEST_PLAN.md`：测试总计划

专门用来描述**测试设计与预期行为**。

- 长期稳定，不轻易修改
- 不要加任何日记型，进度型的记录
- 覆盖测试层级：单元、集成、端到端
- 分成几个阶段
- 包含模块如rag,embedder,tools，router，pipeline等
- 包含测试链路，缺陷和待决策等问题

### `TESTING_GUIDE.md`：测试实施规范

专门写测试规范，如pytest,测试文件的命名与用例。

- 也要保证长期稳定不轻易修改
- 不要加任何日记型的记录

### `TEST_STATUS.md`：测试进度与结果

- 用来记录最近一次验收只作更新覆盖，而非追加
- 真实数据存到runs下

<aside class="callout">
<p class="t">补充 · 依据：由「真实数据存到 runs 下」推导</p>
<p>STATUS 里留的是结论和指针，指向 <code>runs/</code> 里的具体报告，不把日志搬进 md。要看历史上某次跑了什么，去 <code>runs/</code> 或翻 git —— 不要在 STATUS 里往下堆。</p>
</aside>

### `AGENTS.md`：testing/ 文档怎么读和更新

AGENTS.md文档用来记录testing/文档怎么读和更新，如文档之间做指向引用而非重复复制。
