# 复杂度分析：够用就好的版本

复杂度不是数学考试，它的唯一用途是：**在写代码之前，判断这个思路会不会超时。**

## 大 O 只看最高阶

`3n² + 100n + 5000` 的复杂度是 **O(n²)**。

因为 n 变大时，低阶项和常数会被吞掉：

| n | 3n² | 100n | 占比 |
| --- | --- | --- | --- |
| 10 | 300 | 1,000 | 低阶更大 |
| 1,000 | 3,000,000 | 100,000 | 3% |
| 100,000 | 3×10¹⁰ | 10⁷ | 0.03% |

所以写复杂度时，**常数一律扔掉，只留最大的那个**。

## 常见复杂度，从快到慢

| 复杂度 | 叫法 | n = 10⁵ 时大概多少操作 |
| --- | --- | --- |
| O(1) | 常数 | 1 |
| O(log n) | 对数 | 17 |
| O(n) | 线性 | 100,000 |
| O(n log n) | 线性对数 | 1,700,000 |
| O(n²) | 平方 | 10,000,000,000（超时） |
| O(2ⁿ) | 指数 | 无法计算 |

## 一眼估算：数循环

看嵌套层数，看每层跑几次。

```cpp
// O(n)：一层循环
for (int i = 0; i < n; i++) { ... }

// O(n²)：两层嵌套，各跑 n 次
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) { ... }

// O(n log n)：外层 n，内层每轮减半
for (int i = 0; i < n; i++)
    for (int j = n; j > 0; j /= 2) { ... }

// O(log n)：只减半，不套外层
int j = n;
while (j > 0) { j /= 2; }
```

**每轮把问题规模除以 2 → 出现 log**。这是最值得记住的一条。

## 递归的复杂度

递归不能直接数循环，看**递归树的节点数**：

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

每个节点分叉 2 次，树高 n，节点数约 2ⁿ → **O(2ⁿ)**。这就是为什么斐波那契不能用朴素递归。

## 实战判断线

拿到题，先看约束里的 `n` 范围，再倒推算法：

| 题目给的 n | 能用的复杂度 | 通常对应 |
| --- | --- | --- |
| ≤ 20 | O(2ⁿ)、O(n!) | 回溯、暴力枚举 |
| ≤ 500 | O(n³) | 三重循环、区间 DP |
| ≤ 5,000 | O(n²) | 双重循环、二维 DP |
| ≤ 10⁵ | O(n log n) | 排序、二分、堆 |
| ≤ 10⁸ | O(n) | 一次遍历、哈希 |
| 更大 | O(log n)、O(1) | 数学、二分 |

**记熟这张表，比记十个算法模板有用。**
